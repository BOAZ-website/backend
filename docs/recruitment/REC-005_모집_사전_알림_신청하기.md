## 📝 개요

동아리 모집 시작 전 사전 알림을 받고자 하는 사용자의 이메일을 등록한다.
모집 공고가 오픈될 때 구독자에게 알림을 발송하기 위한 정보를 수집한다.

---

## 💾 데이터 구조 (ERD)

---

## 📐 비즈니스 규칙

- [ ] `email`은 반드시 입력해야 한다.
- [ ] 동일한 `email`로 중복 구독 신청 시 에러를 반환한다.
- [ ] `email` 형식이 유효하지 않으면 에러를 반환한다.
- [ ] `created_at`은 서버 시점 기준으로 자동 저장한다. (클라이언트 입력값 사용 안 함)

---

## ⚠️ 예외 처리

| 상황 | HTTP 상태 | 에러 코드 | 사용자 메시지 |
|------|-----------|-----------|--------------|
| `email` 누락 | 400 | `INVALID_INPUT_VALUE` | 이메일을 입력해주세요. |
| 유효하지 않은 이메일 형식 | 400 | `INVALID_EMAIL_FORMAT` | 유효하지 않은 이메일 형식입니다. |
| 이미 구독 중인 이메일 | 409 | `DUPLICATE_EMAIL` | 이미 구독 신청된 이메일입니다. |
| 서버 내부 오류 | 500 | `INTERNAL_SERVER_ERROR` | 서버 오류가 발생했습니다. 잠시 후 다시 시도해주세요. |

---

## 🔌 API 스펙

> 협의 상태: ⚪ 미협의

**Request**

```
POST /api/v1/recruitment/subscriptions
```

| 파라미터 | 위치 | 타입 | 필수 | 설명 |
|---------|------|------|------|------|
| email | Body | String | ✅ | 구독 이메일 |

**Request 예시**

```json
{
  "email": "example@gmail.com"
}
```

**Response (201 Created)**

```json
{
  "status": 201,
  "data": {
    "email": "example@gmail.com"
  }
}
```

**Response (409 Conflict)**

```json
{
  "status": 409,
  "error_code": "DUPLICATE_EMAIL",
  "message": "이미 구독 신청된 이메일입니다."
}
```

**협의 포인트**

- [x] `email`과 `phone` 중 하나만 필수로 할지, 둘 다 입력받을지 ⇒ `email`로만 결정
- [x] 중복 시 200 OK + 안내 메시지 vs 409 Conflict ⇒ 409 Conflict
- [x] 응답에 `id`, `created_at`까지 반환할지, 단순 성공 메시지만 반환할지

## 🧠 의사결정 이력

| 날짜 | 고민했던 선택지 | 최종 결정 | 결정 이유 |
|------|---------------|-----------|-----------|
| - | `email` 단독 필수 vs `email` or `phone` 하나 이상 필수 | `email`로 하도록 결정 | 전화번호로 문자를 전송 시 추가 비용이 발생하는 문제를 고려해 email만 받도록 결정 |
| - | 중복 시 200 OK + 안내 메시지 vs 409 Conflict | 409 Conflict | 중복 구독은 명확한 충돌 상황이므로 HTTP 표준에 맞게 409 반환이 적절 |
| - | `created_at` 클라이언트 입력 vs 서버 자동 저장 | 서버 자동 저장 | 클라이언트 시간은 조작 가능성이 있으므로 서버 시점 기준이 신뢰성 높음 |
