# 지원서 임시저장하기

| 항목 | 내용 |
|------|------|
| ID | REC-007 |
| HTTP Method | PUT |
| Domain | Recruitment |
| 화면 | User |
| 상태 | 완료 |
| 우선순위 | P1 |
| Notion URL | - |

---

## 📝 개요

로그인한 사용자가 지원서를 작성하는 도중 임시저장한다.
모든 필드는 선택 항목으로, 부분 저장이 허용된다.
기존 임시저장(DRAFT) 지원서가 있으면 덮어쓰고, 없으면 새로 생성한다 (upsert).
최종 제출(`SUBMITTED`) 후에는 임시저장이 불가하다.

---

## 📐 비즈니스 규칙

- [ ] 로그인한 사용자만 임시저장할 수 있다.
- [ ] 모집 기간(start_date ~ end_date) 내에만 임시저장할 수 있다.
- [ ] 모든 필드는 선택 항목이며, 일부 필드만 전송해도 저장된다.
- [ ] 해당 모집 공고에 기존 `DRAFT` 지원서가 있으면 덮어쓴다.
- [ ] 해당 모집 공고에 기존 `DRAFT` 지원서가 없으면 새로 생성한다.
- [ ] 해당 모집 공고에 이미 `SUBMITTED` 상태의 지원서가 있으면 임시저장할 수 없다.
- [ ] `answers`가 포함된 경우, 기존 answers를 전부 삭제하고 전달된 항목으로 교체한다.
- [ ] `answers`가 포함되지 않은 경우(null), 기존 answers를 그대로 유지한다.
- [ ] 답변 타입 검증은 제출(REC-004)보다 느슨하게 적용한다. 필수/전체-빈-배열 규칙은 검증하지 않으나, TABLE 단일선택의 값은 문자열, 복수선택의 값은 배열이어야 한다(`INVALID_ANSWER_TYPE`).

---

## ⚠️ 예외 처리

| 상황 | HTTP 상태 | 에러 코드 | 사용자 메시지 |
|------|-----------|-----------|--------------|
| AccessToken 미포함 | 401 | `TOKEN_NOT_FOUND` | 토큰이 존재하지 않습니다. |
| AccessToken 형식 오류 또는 위변조 | 401 | `INVALID_TOKEN` | 유효하지 않은 토큰입니다. |
| AccessToken 만료 | 401 | `EXPIRED_TOKEN` | 만료된 토큰입니다. |
| `recruitmentId` 경로 변수에 숫자가 아닌 값 입력 | 400 | `INVALID_PARAMETER_TYPE` | 파라미터 'recruitmentId'의 값이 올바르지 않습니다. |
| 존재하지 않는 모집 공고 | 404 | `RECRUITMENT_NOT_FOUND` | 해당 모집 공고를 찾을 수 없습니다. |
| 모집 기간이 아닌 경우 | 409 | `RECRUITMENT_CLOSED` | 모집이 마감되었습니다. |
| 이미 제출된 지원서 존재 | 403 | `APPLICATION_ALREADY_SUBMITTED` | 제출된 지원서에 접근할 수 없습니다. |
| 데이터베이스/서버 내부 오류 | 500 | `INTERNAL_SERVER_ERROR` | 서버 내부 오류가 발생했습니다. |

## 🔌 API 스펙

> 협의 상태: ⚪ 미협의

**Request**

```
PUT /api/v1/recruitment/{recruitmentId}/applications/draft
```

| 파라미터 | 위치 | 타입 | 필수 | 설명 |
|---------|------|------|------|------|
| Authorization | Header | STRING | ✅ | `Bearer {userAccessToken}` |
| recruitmentId | Path | LONG | ✅ | 임시저장할 모집 공고 ID |
| track | Body | STRING | ❌ | 지원 부문 (ENUM: `ANALYSIS`, `VISUALIZATION`, `ENGINEERING`) |
| name | Body | STRING | ❌ | 성명 |
| email | Body | STRING | ❌ | 이메일 |
| phone | Body | STRING | ❌ | 전화번호 |
| university | Body | STRING | ❌ | 대학교 |
| major | Body | STRING | ❌ | 본전공 |
| minor_double_major | Body | ARRAY | ❌ | 부전공/복수전공 목록 |
| last_semester | Body | INT | ❌ | 마지막 재학 학기 |
| military_status | Body | STRING | ❌ | 병역 상태 (ENUM: `COMPLETED_OR_EXEMPT`, `NOT_COMPLETED`) |
| birth_date | Body | STRING | ❌ | 생년월일 (`YYYY-MM-DD`) |
| graduation_date | Body | STRING | ❌ | 졸업 예정 시점 (예: `2026-02`) |
| grad_school_plan | Body | BOOLEAN | ❌ | 대학원 진학 여부 |
| answers | Body | ARRAY | ❌ | 답변 목록. null이면 기존 answers 유지. 빈 배열이면 전체 삭제. |
| answers[].question_id | Body | LONG | 조건부 ✅ | answers 포함 시 필수. 질문 ID |
| answers[].answer | Body | ANY | 조건부 ✅ | answers 포함 시 필수. 답변 내용 |

**Request 예시 — 개인정보 부분 저장**

```json
PUT /api/v1/recruitment/12/applications/draft
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...

{
  "track": "ENGINEERING",
  "name": "홍길동",
  "email": "hong@example.com",
  "phone": "01012345678"
}
```

**Request 예시 — 답변 포함 저장**

```json
PUT /api/v1/recruitment/12/applications/draft
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...

{
  "answers": [
    {
      "question_id": 1,
      "answer": "저는 데이터 엔지니어링에 관심이 많아..."
    }
  ]
}
```

**Response (200 OK — 임시저장 성공)**

```json
{
  "status": 200,
  "data": {
    "applicant_id": 42
  }
}
```

**Response (403 Forbidden — 이미 제출된 지원서)**

```json
{
  "status": 403,
  "error_code": "APPLICATION_ALREADY_SUBMITTED",
  "message": "제출된 지원서에 접근할 수 없습니다."
}
```

**협의 포인트**

- [ ] 임시저장 주기: 프론트에서 몇 초마다 서버로 동기화할지 (DB 쓰기 부하 고려)
- [ ] 모집 마감 후 `DRAFT` 상태로 남은 지원서 처리 방식 (자동 삭제 vs 유지)
- [ ] 이미 `SUBMITTED`인 경우 `403` vs `409` 중 어떤 상태 코드가 적절한지

## 🧠 의사결정 이력

| 날짜 | 고민했던 선택지 | 최종 결정 | 결정 이유 |
|------|---------------|-----------|-----------|
| 2026-05-16 | answers 부분 merge vs 전체 교체 | 전체 교체 | 부분 merge 로직은 구현이 복잡하고 클라이언트가 전체 상태를 전송하는 것이 단순. answers가 null이면 기존 유지로 구분 |
| 2026-05-16 | SUBMITTED 후 임시저장 시 `403` vs `409` | `403` | 제출 완료는 정상 상태이므로 리소스 충돌(409)보다 접근 거부(403)가 의미에 더 맞음 |

## 📎 비고

- User 전용 API로, 요청 헤더에 유효한 User AccessToken(`Authorization: Bearer {token}`)이 포함되어야 한다.
- `user_id`는 요청 바디로 받지 않으며, JWT 토큰에서 서버가 직접 추출한다.
- 필드를 전송하지 않은 경우(null) 해당 필드는 변경되지 않는다.
