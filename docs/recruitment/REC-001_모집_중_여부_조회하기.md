## 📝 개요

동아리 웹사이트의 리크루팅 페이지에서 현재 모집이 진행 중인지 여부를 조회한다. 방문자가 모집 상태를 즉시 확인하고 지원 여부를 판단할 수 있도록 한다.

---

## 💾 데이터 구조 (ERD)

---

## 📐 비즈니스 규칙

- [ ] 현재 일시가 `start_date` 이상, `end_date` 이하인 공고만 모집 중으로 간주한다. (날짜 범위 단독 판단)
- [ ] 응답의 `is_active`는 저장된 컬럼이 아니라 날짜 범위로 서버가 계산하는 파생값이다. (Recruitment 엔티티에 is_active 컬럼 없음)
- [ ] 모집 중인 공고가 있으면 해당 기수(`term`)도 함께 반환한다.
- [ ] 모집 중인 공고가 없을 경우 `is_active: false`를 반환한다. (404 아님)

## 🔌 API 스펙

> 협의 상태: ⚪ 미협의

**Request**

```
GET /api/v1/recruitment/status
```

| 파라미터 | 위치 | 타입 | 필수 | 설명 |
|---------|------|------|------|------|
| 없음 | - | - | - | 별도 파라미터 없음 |

**Response (200 OK) - 모집 중**

```json
{
  "status": 200,
  "data": {
    "is_active": true,
    "term": 26
  }
}
```

**Response (200 OK) - 모집 중 아님**

```json
{
  "status": 200,
  "data": {
    "is_active": false
  }
}
```

**협의 포인트**

- [ ] `is_active` 단독 판단 vs 날짜 범위 병행 판단 — 둘 다 충족해야 모집 중으로 볼지 확정 필요
- [ ] 모집 중(날짜 범위 내)인 공고가 여러 개일 경우 처리 방식 (term 최신순 1개 반환 vs 에러 처리)
- [ ] `description` 필드를 이 API에서도 반환할지, 상세 조회 API에서만 반환할지
- [ ] 모집 중 아닐 때 다음 모집 예정 `term`이나 `start_date`도 함께 반환할지
- [ ] 모집 중일 때 다른 정보(`term` 등..)도 함께 반환할지

## 🧠 의사결정 이력

| 날짜 | 고민했던 선택지 | 최종 결정 | 결정 이유 |
|------|---------------|-----------|-----------|
| - | 모집 없을 때 404 반환 vs `is_active: false` 반환 | `is_active: false` 반환 | 비모집 기간이 정상적인 서비스 상태이므로 404는 부적절 |
| - | `is_active` 컬럼 도입 vs 날짜 범위 단독 판단 | 날짜 범위 단독 (is_active 컬럼 미도입) | 수동 플래그는 휴먼 에러 가능성이 있어, start_date~end_date 자동 판단만으로 모집 여부를 결정. 응답의 is_active는 날짜로 계산되는 파생값으로 제공 |

## 📎 비고

- 현재 구현에는 별도 is_active 컬럼이 없으므로, 긴급 마감이 필요하면 `end_date`를 현재 시각 이전으로 수정하여 처리한다. (수동 플래그 기능은 미구현)
- `brochure_url`이 null인 경우 프론트에서 홍보 책자 버튼을 숨기는 방향으로 처리 권장
- `description` 컬럼은 현재 ERD에 "필요없으면 추후 삭제" 명시 — API 응답 포함 여부는 프론트와 협의 후 확정
