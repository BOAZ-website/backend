## 📝 개요

리크루팅 페이지에서 지원서 작성을 위해 현재 진행 중인 모집 공고의 질문 항목들을 조회한다.
개인 정보(이름, 이메일 등) 외의 공통 질문과 부문별 질문을 동적으로 구현하기 위한 데이터를 제공한다.

## 📐 비즈니스 규칙

- [ ] 현재 모집 중인 공고의 질문만 반환한다.
- [ ] 개인 정보에 대한 질문은 제외한다.
- [ ] category가 공통인 질문은 무조건 포함된다. (예: 공통 질문 + 엔지니어링 질문)
- [ ] `track` 파라미터를 기반으로 공통 질문과 해당 부문에 속하는 질문을 함께 반환한다.
- [ ] 모든 질문은 `order_num` 오름차순으로 정렬하여 반환한다.
- [ ] 질문의 `type`은 `TEXT`, `TABLE`로 나뉜다.
- [ ] 질문의 `type`은 `TEXT`, `TABLE`로 나뉜다.
- [ ] 질문의 type이 `TEXT`의 경우, 질문의 내용은 `content`에, 답변 길이 제한은 `limit_length`로 전달된다.
- [ ] 질문의 type이 `TABLE`인 경우, 질문의 내용은 `content`에, 테이블 구조는 `metadata`에 전달된다. `metadata.multiple`이 `true`이면 행별 복수 선택을 허용한다.
- [ ] `description`이 존재하는 경우, 질문 본문 아래에 표시할 보조 설명 텍스트로 전달된다. 없으면 응답에서 생략된다.

## ⚠️ 예외 처리

| 상황 | HTTP 상태 | 에러 코드 | 사용자 메시지 |
|------|-----------|-----------|--------------|
| `track`에 정의되지 않은 문자열 입력 시 | 400 | `INVALID_PARAMETER_TYPE` | 파라미터 'track'의 값이 올바르지 않습니다. |
| `recruitmentId` 등 필수 파라미터 누락 | 400 | `MISSING_PARAMETER` | 요청 파라미터가 누락되었습니다. |
| 공고는 존재하나 현재 모집 기간이 아님 | 400 | `RECRUITMENT_NOT_AVAILABLE` | 현재 지원 가능한 기간이 아닙니다. |
| 존재하지 않는 공고 ID 조회 | 404 | `RECRUITMENT_NOT_FOUND` | 해당 모집 공고를 찾을 수 없습니다. |
| 해당 트랙에 등록된 질문이 없는 경우 | 404 | `QUESTIONS_NOT_FOUND` | 등록된 질문이 없습니다. |

## 🔌 API 스펙

> 협의 상태: ✅ 확정

**Request**

```
GET /api/v1/recruitment/questions
```

| 파라미터 | 위치 | 타입 | 필수 | 설명 |
|---------|------|------|------|------|
| recruitmentId | Query | Long | ✅ | 모집 공고 고유 식별자 |
| track | Query | String | ✅ | 지원 부문 (ENUM: `ANALYSIS`, `VISUALIZATION`, `ENGINEERING`) |

**Request 예시**

```
GET /api/v1/recruitment/questions?recruitmentId=1&track=ENGINEERING
```

## 🧠 의사결정 이력

| 날짜 | 고민했던 선택지 | 최종 결정 | 결정 이유 |
|------|---------------|-----------|-----------|
| 2026-02-22 | 질문별 글자수 제한 반환 여부 | 함께 반환 | 질문별로 최대 답변 글자 수 제한이 다르기 때문 |
| 2026-02-22 | 질문 목록을 카테고리별로 반환 vs 공통과 부문 함께 반환 | 함께 반환 | 한 번 요청으로 모든 질문 데이터를 받는 것이 편리 |
| 2026-06-04 | TABLE 복수선택 구분 방법 (별도 Type `TABLE_MULTI` vs `metadata.multiple` 플래그) | `metadata.multiple` 플래그 | `QuestionResponse`가 metadata를 raw JsonNode로 패스스루하므로 백엔드 응답 코드 변경 없이 프론트에 전달됨. 기존 단일선택 데이터 호환 유지. |
| 2026-06-04 | 질문 보조 설명 위치 (`content` 합치기 vs `metadata` vs 전용 컬럼) | 전용 `description` 컬럼 | `metadata`는 TABLE 전용이고, content와 합치면 프론트가 분리 렌더링 불가. 질문 타입과 무관한 범용 필드로 분리. |
